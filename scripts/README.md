# Checks

- `npm run bake:instruments`: generate dry mono sample banks for all 188 catalog instruments under `public/instrument-banks/`. Runs three independent bake processes; use `-- --jobs=1` to limit memory/CPU, `-- --instrument=piano` for one instrument, or `-- --force` to regenerate. Unchanged banks are reused using a source fingerprint. Baking fails on silent/non-finite audio and records catalog coverage in `index.json`.
- `node --import tsx --test scripts/baked-instruments.test.ts`: sample selection, kit identity, sustain looping, pitch/microtuning, mixer controls, cancellation, loading and export routing.
- `npm run audit:baked`: examine every baked sample's format, bounds, non-silence, sustain loop bounds, settled-control bake metadata, pitch spacing, every key/component’s measured gain and full-sample peak headroom, velocity-layer ordering, and actual playback of every sampled note/technique. Includes a spectral regression for the piano/tres attacks that previously swept into the wrong register. Writes `audit/baked-audio-quality.json`; these numerical checks do not establish perceptual realism.

Playback and exports prefer quality-version-2 banks when present. Instruments load lazily, with a 96 MiB decoded-bank budget per renderer process. Banks store anti-aliased 22.05 kHz mono PCM16 with per-sample level restoration; output and studio mastering remain at 44.1 kHz. This trades the top octave of treble for manageable static asset size. Each bake settles pitch/delay controls for 8,192 frames with the gate closed before recording an attack. Banks contain two velocity layers (48/100), nine pitched anchors spaced six semitones apart (lower anchors for bass), all declared kit pitches, and tone plus authored pizzicato/chapa/mute/slap/rimshot/open/marcato variants. Sample transposition is capped at three semitones; unsupported source techniques and unavailable pitches fall back to physics rather than substituting an unrelated sound. Dynamics/phrasing aliases can share a tone sample. Banks replace legacy model makeup compensation with measured RMS calibration for every pitch and kit component. Velocity-100 attacks target 0.08 RMS (0.16 for bass in its actual register), subject to full-sample peak limits of 0.35 (0.60 for bass). Authored kit trims are preserved within those limits. Soft layers and techniques retain their source character while bounded RMS/peak trims keep soft notes below normal notes and prevent sudden articulation overloads. Role gain, user faders and expressive dynamics remain independent; these are dry reference levels, not a claim that every song should have equal stem loudness. `-- --calibrate` updates trims from existing version-2 audio without rerendering it. The renderer honors gain/pan/expression/brightness/mute and pitch bends, and loops held sources with a crossfade. Continuous bow/bellows/contact/resonance changes and genre-specific physical timbre remain approximations. Decaying tails are bounded to 12 seconds with a final fade. Use `synthesisMode: 'physical'` in render options for the original reference renderer.

The generated public banks are deployment assets: `vite build` copies them to `dist`. Regenerate after physical renderer/catalog changes. Baking does not publish or deploy them. The first bank load still incurs a download; cached playback avoids physical DSP.

- `npm run check`: one catalog pass over every exported data property and resolved style/profile, then focused musical, sound-resolution, solo, mix and playback regressions. No PCM rendering. Stops at the first failed gate.
- `npm run audit:catalog`: only the complete data/profile pass: references, finite numbers, probabilities, ranges, weighted distributions, provenance, physical DSP, gestures, kits, solo policies and mix settings.
- `npm run check:audio`: fast gates first (reused when the source fingerprint is unchanged), then PCM regression fixtures, representative instrument mechanisms and two short ensemble excerpts per selected style. `check:full` is an alias; neither renders the catalog.
- `npm run audit:browser`: native playback buffers and Web Audio master in the chosen browser at `http://127.0.0.1:3001/scripts/browser-mix-audit.html`. Defaults to renderer coverage; a specific style can be selected.
- `npm run test:audio -- --style=<id>`: targeted portable PCM. Add `--encoded` for MP3 stream and decoded loudness checks (requires ffmpeg/ffprobe), `--save` to retain clips in `/tmp/mixgenres-audio-regression`, or `--details` for per-stem diagnostics.
- `npm run audit:instrument-render -- --instrument=<id>`: targeted physical-model probes. Defaults to representatives covering shared modules, model IDs, excitation and sustain types. `--details` retains individual metrics.
- `npm run audit:report`: show the last run's result and whether its sources have changed.

Reports in `audit/*.json` contain coverage and actionable findings. Successful runs print one line per gate. Type checking belongs to `lint`/`build`; it is not repeated inside audits. `test:all` adds targeted audio and a production build.

`audit/` is disposable generated output, ignored by Git. The app never reads it. Delete the entire folder at any time; checks regenerate reports and rerun fast gates if their optional cache is absent. The report viewer prints a short message when no saved report exists.

All styles and profiles receive structural checks; numerical variations of the same renderer do not require separate audio renders. The audio selector automatically includes newly introduced renderer mechanisms. Explicit IDs are available for changes needing listening or focused diagnosis.

Node checks cover stems, portable mixing and export. Browser checks cover the native master and the PCM buffer used by the player. Passing either says what was measured; it does not claim every device or perceptual arrangement has been verified. Short-excerpt loudness is not a whole-song target. Isolated stem headroom is not reported as a clipping failure.
